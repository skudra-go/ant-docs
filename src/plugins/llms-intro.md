ant is newer than most models' training data, and its API is not GORM's, Bun's or ent's. Don't guess from those: calls such as `db.Where("age > ?", 18)`, `Preload`, `AutoMigrate`, `Model(&u).Updates` and `First(&u)` don't exist. Check a name with `go doc github.com/skudra-go/ant <Name>` or the pages below. ant's repo has a skill for coding agents, `skills/ant/SKILL.md`, which installs with `npx skills add skudra-go/ant` or, in Claude Code, `/plugin marketplace add skudra-go/ant`.

The rules that matter most:

- Models are plain structs. A database is a struct that embeds `ant.Context` and holds an `ant.Table[T]` per model; `ant.Open[AppDB](ctx, postgres.Dialect, dsn)` fills it in, and refuses at startup a model it can't map, such as an unknown tag key or `[]*Post` where `[]Post` is meant. The application imports the driver.
- Columns are field pointers into a probe, never strings: `var Users = ant.Fields[User]()`, then `ant.Gt(&Users.Age, 18)`. The value must have the field's type. Every helper takes a field of any type, so a nullable, `uuid.UUID` or `decimal.Decimal` field orders, compares and sums like a plain one. A pointer from another model's probe is `ant.ErrWrongModel` at run time.
- Queries chain from a table and run at the call that takes `ctx`: `All` (returns `[]*T`), `First`, `Single`, `Find`, `Count`, `Exists`, `Each`. Builders never return errors; the terminal call does. NULL reads as Go: `ant.Eq(&Users.Bio, nil)` is `IS NULL`, and on a nullable column `Ne`, `NotIn` and `Not(Eq(...))` with a value match the NULL rows too.
- Relations are fields (`Posts []Post`, `User *User`) found by name (`Post.UserID`). They load only through `Include` or `IncludeOne`; an unloaded relation is `nil`. There is no lazy loading.
- `Update` and `Delete` hang off a query, with explicit assignments: `db.Users.Where(...).Update(ctx, ant.Set(&Users.Age, 0))`. Without a condition they return `ant.ErrNoCondition`.
- The context from `ant.Open` doesn't track: share it for reads, inserts and bulk writes. A session, `ant.Session(db)`, tracks what it loads: change the struct and call `session.SaveChanges(ctx)`, which writes only the changed columns. Take one session per request or goroutine, and load and save through the same one: an entity loaded through `db` or another session isn't saved, and `SaveChanges` still returns nil. `SaveChanges` on the root returns `ant.ErrNoTracking`. Removing an element from a loaded relation slice deletes that row on the next save.
- Decode a request body into an input struct of the fields the client may set, not into a model: a decoded model brings its key, timestamps and relations, and ant writes them as given.
- `db.Tx(ctx, func(tx *AppDB) error { ... })` runs a transaction; use `tx` inside it, or give code that holds `db` the context `ant.InTx(ctx, tx)`. A hook's `ctx` is already bound to its write's transaction.
- Match errors with `errors.Is`: `ant.ErrNotFound`, `ant.ErrConcurrency`, `ant.ErrConcurrentUse`, `ant.ErrNoTracking`, `ant.ErrZeroKey`, `ant.ErrUnsupported`.
- PostgreSQL has everything. MySQL, MariaDB, SQLite and SQL Server have queries, writes and transactions, but no migrations. Migrations are plain SQL that `go run ./cmd/migrate diff <name>` writes from the structs, and there are no down migrations.

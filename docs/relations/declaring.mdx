---
title: Declaring relations
description: Declare a relation as a field on the struct, found by name or configured in Go.
---

A relation is a field on the struct. `[]Post` is one-to-many, and `*User` is many-to-one or one-to-one. ant finds the foreign key by name, so most relations need no configuration.

## Declare a relation by name

```go
type Person struct {
	ID       int64
	Name     string
	// spot-start
	Passport *Passport // one-to-one, through Passport.PersonID
	Pets     []Pet     // one-to-many, through Pet.PersonID
	// spot-end
}

type Passport struct {
	ID       int64
	PersonID int64
	Number   string
}

type Pet struct {
	ID       int64
	PersonID int64
	Name     string
	// spot-next-line
	Person   *Person // many-to-one, through Pet.PersonID
}
```

The foreign key is the owner's name plus `ID`: `Pet.PersonID` joins to `Person.ID`. Relation fields aren't columns, and a query leaves them empty until you [load them](/relations/loading). You can declare a relation on one side only, and use it from that side.

```go
users, err := db.Users.Include(&U.Posts).All(ctx)
// SELECT ... FROM "users"
// SELECT ... FROM "posts" WHERE "posts"."user_id" IN ($1, $2, $3)
```

## Name the foreign key

When names can't find the key, `Configure` names it. Either side can do this.

```go
type Author struct {
	ID     int64
	Handle string
	Books  []Book
}

func (Author) Configure(b *ant.ModelBuilder[Author]) {
	// spot-next-line
	b.HasMany(&Au.Books).ForeignKey(&Bk.WriterID).OnDelete(ant.Cascade)
}

type Book struct {
	ID       int64
	WriterID int64
	Title    string
	Writer   *Author
}

func (Book) Configure(b *ant.ModelBuilder[Book]) {
	// spot-next-line
	b.BelongsTo(&Bk.Writer).ForeignKey(&Bk.WriterID)
}

var (
	Au = ant.Fields[Author]()
	Bk = ant.Fields[Book]()
)
```

| Call | Declares |
| --- | --- |
| `b.HasMany(&U.Posts)` | one-to-many |
| `b.HasOne(&U.Passport)` | one-to-one, key on the other side |
| `b.BelongsTo(&P.User)` | many-to-one, key on this side |
| `b.ManyToMany(&U.Roles)` | [through a join table](/relations/many-to-many) |

A relation that nothing connects returns `ant.ErrNoForeignKey` at the terminal call (`All`, `First` and so on), not when the model is declared.

## Join on a column other than the key

`References` points at another column of the owner, which must be unique. Use it when children refer to a natural key such as a handle or a SKU.

type Author struct {

```go
type Quote struct {
	ID           int64
	AuthorHandle string
	Text         string
}

func (Author) Configure(b *ant.ModelBuilder[Author]) {
	// spot-next-line
	b.HasMany(&Au.Quotes).ForeignKey(&Qt.AuthorHandle).References(&Au.Handle)
}

var Qt = ant.Fields[Quote]()
```

## Choose what happens on delete

The foreign key is `NO ACTION` unless you set it, so deleting a parent that still has children fails and nothing is removed that you didn't ask for.

```go
func (Post) Configure(b *ant.ModelBuilder[Post]) {
	// spot-next-line
	b.BelongsTo(&P.User).OnDelete(ant.Cascade).OnUpdate(ant.NoAction)
}
```

The actions are `ant.Cascade` (delete the children too), `ant.SetNull`, `ant.Restrict`, and `ant.NoAction`. They become part of the foreign key in [migrations](/migrations/models-to-tables), and the database enforces them.

## Skip the constraint or the index

```go
func (Post) Configure(b *ant.ModelBuilder[Post]) {
	// spot-start
	b.BelongsTo(&P.User).NoForeignKey() // keep the relation, skip the constraint
	b.BelongsTo(&P.User).NoIndex()      // skip the automatic index
	// spot-end
}
```

## Point a model at itself

The parent is found through `ParentID`, and the children through the matching back-reference. Use it for trees such as folders and categories.

```go
type Folder struct {
	ID       int64
	// spot-start
	ParentID *int64
	Parent   *Folder
	Children []Folder
	// spot-end
	Name     string
}
```

Use a pointer key, so a root can have no parent. For many-to-many, [declare it through a join table](/relations/many-to-many).

A many-to-many relation goes through a join table. Declare it on either side or both, and [migrations](/migrations/models-to-tables) create the table once.

## Declare a many-to-many relation

```go
type Student struct {
	ID      int64
	Name    string
	Courses []Course
}

func (Student) Configure(b *ant.ModelBuilder[Student]) {
	// spot-next-line
	b.ManyToMany(&St.Courses).Through("enrollments")
}

type Course struct {
	ID    int64
	Title string
}

var (
	St = ant.Fields[Student]()
	Cs = ant.Fields[Course]()
)
```

The join table's columns default to `student_id` and `course_id` here.

### Name the join columns

`PivotColumns` names them. A self-referencing relation needs it, since both columns would otherwise get the same name.

```go
type Person struct {
	ID      int64
	Friends []Person
}

func (Person) Configure(b *ant.ModelBuilder[Person]) {
	// spot-next-line
	b.ManyToMany(&Pn.Friends).Through("friendships").PivotColumns("person_id", "friend_id")
}

var Pn = ant.Fields[Person]()
```

## Read through the join table

`Include`, `Has`, `JoinMany`, and `CountRelated` all go through the join table for you. `Include` reads the join table, then the targets, so it is one query more than a one-to-many `Include`:

```go
// spot-next-line
students, err := db.Students.Include(&St.Courses).All(ctx)
// SELECT "students"."id", "students"."name" FROM "students"
// SELECT "student_id", "course_id" FROM "enrollments" WHERE "student_id" IN ($1)
// SELECT "courses"."id", "courses"."title" FROM "courses" WHERE "courses"."id" IN ($1)
```

`Has` filters on the targets without loading them:

```go
// spot-next-line
artists, err := db.Students.Where(ant.Has(&St.Courses, ant.Eq(&Cs.Title, "Art"))).All(ctx)
// SELECT ... FROM "students" WHERE EXISTS (
//   SELECT 1 FROM "courses" AS "ant_related"
//   JOIN "enrollments" AS "ant_related_pivot" ON "ant_related_pivot"."course_id" = "ant_related"."id"
//   WHERE "ant_related_pivot"."student_id" = "students"."id" AND ("ant_related"."title" = $1))
```

## Change the links

These functions change the join table only, never the rows on either side. Both entities must already have their keys.

```go
// spot-start
err := ant.Link(ctx, db, ann, &St.Courses, math, art) // add
// INSERT INTO "enrollments" ("student_id", "course_id") VALUES ($1, $2), ($3, $4) ON CONFLICT DO NOTHING

err = ant.Unlink(ctx, db, ann, &St.Courses, art) // remove
// DELETE FROM "enrollments" WHERE "student_id" = $1 AND "course_id" IN ($2)

err = ant.SyncLinks(ctx, db, ann, &St.Courses, art, music) // make the list exact
// DELETE FROM "enrollments" WHERE "student_id" = $1 AND NOT ("course_id" IN ($2, $3))
// INSERT INTO "enrollments" ("student_id", "course_id") VALUES ($1, $2), ($3, $4) ON CONFLICT DO NOTHING

err = ant.Toggle(ctx, db, ann, &St.Courses, math) // flip each one
// DELETE FROM "enrollments" WHERE "student_id" = $1 AND "course_id" IN ($2) RETURNING "course_id"
// INSERT INTO "enrollments" ("student_id", "course_id") VALUES ($1, $2) ON CONFLICT DO NOTHING
// spot-end
```

Repeating a `Link` is harmless, because the insert ignores links that exist. `SyncLinks` is how a "choose your courses" form saves: pass the ticked boxes and the table ends up matching them. `Toggle` suits a like or follow button: it removes the links that exist and adds the ones that don't.

## Change the links through a tracked slice

A loaded relation can be edited like any slice, and `SaveChanges` updates the links. A new target is inserted and linked. Removing one removes the link, never the course.

```go
session := ant.Session(db)

student, err := session.Students.Include(&St.Courses).Find(ctx, id)

// spot-start
student.Courses = student.Courses[1:]
student.Courses = append(student.Courses, Course{Title: "Drama"})

err = session.SaveChanges(ctx)
// spot-end
```

Setting an element to another course unlinks the old one and links the new one. Pending changes to the slice are lost if you load the relation again before saving: [save first](/relations/loading#include-and-tracked-entities).

A new owner inserted with existing targets links them in the same call. On a session, it is tracked as if you had loaded it with them:

```go
session := ant.Session(db)

cal := &Student{Name: "Cal", Courses: []Course{*math}}

// spot-next-line
err := session.Students.Insert(ctx, cal)
// INSERT INTO "students" ("name") VALUES ($1) RETURNING "id"
// INSERT INTO "enrollments" ("student_id", "course_id") VALUES ($1, $2) ON CONFLICT DO NOTHING
```

## Keep data on the join table

When the join table holds data of its own, like a grade or a date, it's a model. Make it one, with two has-many relations, and you get queries, timestamps, and hooks like any other model. ant has no separate pivot API, on purpose.

```go
// spot-start
type Enrollment struct {
	ant.Base
	StudentID int64
	CourseID  int64
	Grade     *string
}
// spot-end
```

---
title: Partitioned tables
description: Monthly PostgreSQL partitions for append-mostly data with a retention rule.
---

A partitioned table is many tables behind one name. Queries that filter on the partition column skip the rest, and dropping a whole partition frees its space at once, where deleting the same rows would take hours and leave the table bloated. Use it for data that is mostly appended and kept for a fixed time, such as events or logs. It needs PostgreSQL.

## Declare a partitioned model

```go
type Event struct {
	ID         int64
	OccurredAt time.Time
}

func (Event) Configure(b *ant.ModelBuilder[Event]) {
	// spot-start
	b.CompositeKey(ant.F(&E.ID), ant.F(&E.OccurredAt))
	b.PartitionByRange(ant.F(&E.OccurredAt))
	// spot-end
}

var E = ant.Fields[Event]()
```

Migrations create the parent table. A partitioned table's primary key and unique constraints must include the partition column, because PostgreSQL only enforces uniqueness per partition, so the key is composite.

## Create and drop months

Partitions come and go on a schedule, so they aren't migrations, and `drift` ignores them. `postgres.MonthlyPartitions` looks after them. A partition is named `events_2026_10` and runs from midnight UTC on the first of the month. Partitions with other names are left alone.

```go
months, err := postgres.MonthlyPartitions[Event](db)
if err != nil {
	return err
}

// spot-start
created, err := months.Ensure(ctx, time.Now(), 3) // this month and the next three
existing, err := months.List(ctx)                 // what exists
dropped, err := months.DropBefore(ctx, cutoff)    // whole months that ended by cutoff
// spot-end
```

{/*
```go
var cutoff time.Time
```
*/}

`Ensure` is safe to repeat, and to run from several instances. Run it at startup, since a row for a month with no partition is an error, and again on a schedule. `DropBefore` drops only months that ended at or before the cutoff, so no row newer than the cutoff is lost.

## Relate two partitioned tables

A foreign key to a partitioned table needs the whole key, which a relation can't express. Keep the relation for loading, and declare the constraint apart.

```go
type Person struct {
	ID         int64
	EventID    int64
	OccurredAt time.Time
	Event      *Event
}

func (Person) Configure(b *ant.ModelBuilder[Person]) {
	b.PartitionByRange(ant.F(&Pn.OccurredAt))
	// spot-start
	b.BelongsTo(&Pn.Event).ForeignKey(&Pn.EventID).References(&E.ID).NoForeignKey().NoIndex()
	b.ForeignKey(ant.F(&Pn.EventID), ant.F(&Pn.OccurredAt)).
		References(ant.F(&E.ID), ant.F(&E.OccurredAt)).
		OnDelete(ant.Cascade)
		// spot-end
}

var Pn = ant.Fields[Person]()
```

Children copy the parent's time, which puts both rows in matching months. Name both columns in joins, so PostgreSQL pairs each month with its own.

```go
query := db.People.Query().
	// spot-next-line
	JoinOn[Event](ant.EqCol(&Pn.EventID, &E.ID), ant.EqCol(&Pn.OccurredAt, &E.OccurredAt))
```

{/*
```go
type PeopleDB struct {
	ant.Context
	Events ant.Table[Event]
	People ant.Table[Person]
}
```
*/}

Drop children first: `DropBefore` on `Person`, then on `Event`, or PostgreSQL refuses to drop a month the foreign key still points at.

## Limits

- `.Concurrently()` doesn't work on a partitioned table.
- A row outside every partition is an error. A default partition would hide that, then block creating the month later.
- Filter on the partition column wherever you can, or PostgreSQL searches every month.

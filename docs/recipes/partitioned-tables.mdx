Queries that filter on the partition column skip the other partitions. Dropping a partition frees its space at once, where deleting the same rows would take hours and leave the table bloated. Use it for append-mostly data kept for a fixed time, such as events or logs. It needs PostgreSQL.

## Declare a partitioned model

```go
type Event struct {
	ID         int64
	OccurredAt time.Time
}

func (Event) Configure(b *ant.ModelBuilder[Event]) {
	// spot-start
	b.CompositeKey(ant.F(&Events.ID), ant.F(&Events.OccurredAt))
	b.PartitionByRange(ant.F(&Events.OccurredAt))
	// spot-end
}

var Events = ant.Fields[Event]()
```

Migrations create the parent table. Primary key and unique constraints must include the partition column, since PostgreSQL enforces uniqueness per partition, so the key is composite.

## Create and drop months

Partitions come and go on a schedule, so they aren't migrations and `drift` ignores them. `postgres.MonthlyPartitions` looks after them. A partition it creates is named `events_2026_10` and runs from midnight UTC on the first of the month.

```go
months, err := postgres.MonthlyPartitions[Event](db)
if err != nil {
	return err
}

// spot-start
created, err := months.Ensure(ctx, time.Now(), 3) // this month and the next three
existing, err := months.List(ctx)                 // what exists
dropped, err := months.DropBefore(ctx, cutoff)    // whole months that ended by cutoff
// spot-end
```

{/*
```go
var cutoff time.Time
```
*/}

`Ensure` is safe to repeat and to run from several instances. Run it at startup, since a row for a month with no partition is an error, and again on a schedule. `DropBefore` drops only months that ended at or before the cutoff.

Each `postgres.Partition` that `List` returns has `Name` and `Month`, and encodes as `{"name":"events_2026_10","month":"2026-10-01T00:00:00Z"}`.

### Months someone else made {#months-by-bounds}

A month is found by its bounds, not its name: any partition that runs from midnight UTC on the first of a month to the first of the next is that month. So a table whose months were made before ant looked after it, such as Pagila's `payment_p2022_01`, is listed, `Ensure` doesn't make its months again, and `DropBefore` drops them on time. The partition column can be `timestamptz`, `timestamp` or `date`.

A partition over any other span, such as a quarter, or a default partition, is not a month, and is left alone. If the name `Ensure` would give a month, such as `payment_2026_04`, is already taken by a partition over another span, `Ensure` returns an error that names it, rather than report the month covered.

## Relate two partitioned tables

A foreign key to a partitioned table needs the whole key, which a relation can't express. Keep the relation for loading and declare the constraint separately.

```go
type Person struct {
	ID         int64
	EventID    int64
	OccurredAt time.Time
	Event      *Event
}

func (Person) Configure(b *ant.ModelBuilder[Person]) {
	b.PartitionByRange(ant.F(&Persons.OccurredAt))
	// spot-start
	b.BelongsTo(&Persons.Event).ForeignKey(&Persons.EventID).References(&Events.ID).NoForeignKey().NoIndex()
	b.ForeignKey(ant.F(&Persons.EventID), ant.F(&Persons.OccurredAt)).
		References(ant.F(&Events.ID), ant.F(&Events.OccurredAt)).
		OnDelete(ant.Cascade)
		// spot-end
}

var Persons = ant.Fields[Person]()
```

Children copy the parent's time, which puts both rows in matching months. Name both columns in joins, so PostgreSQL pairs each month with its own.

```go
query := db.People.Query().
	// spot-next-line
	JoinOn[Event](ant.EqCol(&Persons.EventID, &Events.ID), ant.EqCol(&Persons.OccurredAt, &Events.OccurredAt))
```

{/*
```go
type PeopleDB struct {
	ant.Context
	Events ant.Table[Event]

}
```
*/}

Drop children first: `DropBefore` on `Person`, then on `Event`, or PostgreSQL refuses to drop a month the foreign key still points at.

## Limits

- `.Concurrently()` doesn't work on a partitioned table.
- A row outside every partition is an error. A default partition would hide that, then block creating the month later.
- Filter on the partition column wherever you can, or PostgreSQL searches every month.

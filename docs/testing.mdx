Test against a real database. ant has no in-memory fake, on purpose: a fake accepts SQL the real server would refuse, and hides what constraints, triggers and transactions do. PostgreSQL in a container starts in seconds.

## Set up a database for tests

Build the schema from your real migrations, so a broken migration fails a test before it reaches production.

```go
var shared *models.AppDB

func TestMain(m *testing.M) {
	ctx := context.Background()

	db, err := ant.Open[models.AppDB](ctx, postgres.Dialect, os.Getenv("TEST_DATABASE_URL"))
	if err != nil {
		log.Fatal(err)
	}

	// spot-next-line
	if err := migrate.Up(ctx, db, migrate.Config{FS: migrations.Files}); err != nil {
		log.Fatal(err)
	}

	shared = db

	os.Exit(m.Run())
}
```

For quick experiments, `db.EnsureCreated(ctx)` builds tables straight from the structs.

A local database for the tests:

```yaml
# docker-compose.yml
services:
  db:
    image: postgres:17
    environment: { POSTGRES_USER: app, POSTGRES_PASSWORD: app, POSTGRES_DB: app }
    ports: ["127.0.0.1:55432:5432"]
```

### Skip when no database is set

A test that needs the database skips itself when `TEST_DATABASE_URL` is empty, so `go test ./...` works anywhere:

```go
func TestNeedsDatabase(t *testing.T) {
	if os.Getenv("TEST_DATABASE_URL") == "" {
		t.Skip("TEST_DATABASE_URL is not set")
	}
}
```

A skipped test is not a passing test. Check the skip count in CI.

## Roll each test back

`anttest.Isolate` gives a test a context bound to a transaction that rolls back when the test ends, so tests can share a database and need no cleanup.

```go
func TestSignup(t *testing.T) {
	// spot-next-line
	db := anttest.Isolate(t, shared)

	err := db.Users.Insert(t.Context(), &models.User{Name: "Ann", Email: "ann@example.com"})
	if err != nil {
		t.Fatal(err)
	}
}
```

The test sees its own writes. Code that commits for real, such as through a second connection, doesn't see them, so a test of concurrency needs a database of its own. An isolated context is one connection, so don't share it between goroutines that run at once.

## Make entities with factories

A factory makes valid entities, so a test spells out only what it cares about. The number it passes in keeps values unique.

```go
// spot-start
var Users = anttest.NewFactory(func(n int) *models.User {
	return &models.User{
		Name:  fmt.Sprintf("user %d", n),
		Email: fmt.Sprintf("u%d@example.com", n),
	}
})
// spot-end

func TestFactories(t *testing.T) {
	db := anttest.Isolate(t, shared)

	// spot-start
	user := Users.Create(t, &db.Users)                                      // in the database
	draft := Users.Build()                                                  // in memory
	many := Users.CreateMany(t, &db.Users, 10)                              // several
	young := Users.Create(t, &db.Users, func(u *models.User) { u.Age = 5 }) // one override
	// spot-end
}
```

### Name a state

`With` returns a new factory with the changes applied and leaves the original alone.

```go
func TestAdmin(t *testing.T) {
	db := anttest.Isolate(t, shared)

	// spot-next-line
	admin := Users.With(func(u *models.User) { u.Admin = true })

	boss := admin.Create(t, &db.Users)
}
```

`AfterBuild` and `AfterCreate` add callbacks that run on each entity.

### Share one parent

`anttest.Recycle` creates one parent the first time a child needs it and hands the same one to the rest.

```go
func TestRecycle(t *testing.T) {
	db := anttest.Isolate(t, shared)

	// spot-next-line
	author := anttest.Recycle(Users, &db.Users)

	posts := anttest.NewFactory(func(n int) *models.Post {
		return &models.Post{Title: fmt.Sprintf("post %d", n), UserID: author.Get(t).ID}
	})

	posts.CreateMany(t, &db.Posts, 3) // one author
}
```

## Load fixtures

`anttest.Load` loads rows from JSON files named after their tables, for data that doesn't change. Each file is an array of objects keyed by column:

```json
[{"id": 1, "name": "Ada", "created_at": "2026-01-01T00:00:00Z"}]
```

Rows go in as written, with no hooks, Go defaults or timestamps, so parents come first.

```go
//go:embed testdata
var data embed.FS

func TestWithFixtures(t *testing.T) {
	db := anttest.Isolate(t, shared)

	// spot-next-line
	anttest.Load(t, db, data, "testdata/users.json", "testdata/posts.json")
}
```

## Check the SQL

`q.ToSQL()` returns a query's SQL with no database, which suits a test of a query builder. For anything else, run the query: what matters is what the database returns.

[`ant.DryRun`](/tooling/inspecting-queries#dryrun) runs real code in a transaction and returns every statement, which shows what a unit of work decides to write. [antvet](/tooling/antvet) catches mistakes before tests run.

:::warning[SQLite is not a stand-in]

SQLite is tempting for speed, but it has no `FOR UPDATE`, no enum types, different date handling and looser typing, so a test can pass there and fail in production. Test on the database you deploy. Where SQLite is what you deploy, ant's dialect runs queries and writes, but migrations aren't available, so create the tables with your own SQL.

:::

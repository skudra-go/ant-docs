## How `&Users.Age` becomes a column

`&Users.Age` is a `*int`, so the compiler checks the field name, and checks that the value compared with it is an `int`.

<FieldTrace />

### How ant finds the column

`ant.Fields[User]()` allocates one empty `User` per model type and records its address. `&Users.Age` is an address inside that value, so ant subtracts the start address to get the field's offset, then matches the offset and the pointer's type against the fields it read from `User` by reflection. It checks the type too, because a struct and its first field share an address. Resolving a field pointer takes about 20 ns and allocates nothing.

This needs the probe's address to stay fixed, so ant pins each probe with [`runtime.Pinner`](https://pkg.go.dev/runtime#Pinner) when it allocates it. The address then holds even under a moving collector, which Go does not have today. A test in ant, `TestProbeSurvivesGC`, guards it.

<CollapsibleCode title="internal/meta/meta.go" note="Resolve, simplified">

```go no-check
func Resolve[V any](ptr *V) (Ref, bool) {
	addr := uintptr(unsafe.Pointer(ptr))
	t := reflect.TypeFor[V]()

	for _, p := range probes {
		if addr < p.base || addr >= p.base+p.model.Type.Size() {
			continue
		}

		off := addr - p.base

		for _, f := range p.model.Fields {
			if f.Offset == off && f.Type == t {
				return Ref{Model: p.model, Field: f}, true
			}
		}
	}

	return Ref{}, false
}
```

</CollapsibleCode>

### Zero values disappear

GORM's `Updates`, Bun's `OmitZero` and xorm's `Update` skip zero-valued fields.

<SaveDemo />

<Compare>
<Others>
<Lib>

```go marks no-check title="GORM"
db.Model(&user).Updates(User{
	Name:   "Ada",
	⟦-:Age:    0⟧,
	⟦-:Active: false⟧,
})
```

```sql no-check title="Sends"
UPDATE "users" SET "updated_at"='…',"name"='Ada' WHERE "id" = 1
-- no age, no active
```

`Select("Age", "Active")` or a map writes them.

</Lib>
<Lib>

```go marks no-check title="Bun"
_, err := db.NewUpdate().Model(&user).
	⟦-:OmitZero()⟧.
	WherePK().
	Exec(ctx)
```

```sql no-check title="Sends"
UPDATE "users" AS "user" SET "name" = 'Ada' WHERE ("user"."id" = 1)
-- no age, no active
```

`OmitZero` is opt-in. Without it, Bun writes every column.

</Lib>
<Lib>

```go marks no-check title="xorm"
engine.ID(id).Update(&User{
	Name: "Ada",
	⟦-:Age:  0⟧,
})
```

`Cols` or `AllCols` writes them.

</Lib>
</Others>
<Ant>

```go marks title="ant"
user, err := db.Users.Find(ctx, id)

user.Age = 0
user.Active = false

err = ⟦+:db.SaveChanges(ctx)⟧
```

```sql marks title="Sends"
UPDATE "users" SET ⟦+:"age" = $1⟧, ⟦+:"active" = $2⟧, "updated_at" = $3
WHERE "users"."id" = $4
```

- ant compares against what it loaded, so `0`, `false`, `""` and `nil` are changes.
- Zero has a special meaning in only two places: a zero integer key is generated by the database, and a zero field tagged [`default`](/models/nullable-and-defaults#database-defaults) is left for the database to fill in.

### Saving undoes someone else's change

When a save writes the whole row back, the last of two requests undoes the other's change.

<LostUpdate />

<Compare>
<Others>
<Lib>

```go marks no-check title="GORM"
user.Name = "Ada L."

⟦-:db.Save(&user)⟧
```

```sql marks no-check title="Sends"
UPDATE "users" SET "created_at"='…',"updated_at"='…',"name"='Ada L.',
	⟦-:"plan"='free'⟧,"age"=36,"active"=true
WHERE "id" = 1
```

Bun's `Update` on a model also writes every field.

</Lib>
<Lib>

```go marks no-check title="ent"
u, err = u.Update().
	SetName("Ada L.").
	Save(ctx)
```

Only the fields in the setter chain are written. The code that saves has to know which fields changed.

</Lib>
<Lib>

```sql marks no-check title="sqlc"
UPDATE users SET
	name = ⟦-:coalesce(sqlc.narg('name'), name)⟧,
	plan = coalesce(sqlc.narg('plan'), plan)
WHERE id = sqlc.arg('id');
```

Safe, with a statement for each shape of update or a `coalesce` for every optional column.

</Lib>
</Others>
<Ant>

```go marks title="ant"
user, err := db.Users.Find(ctx, id)

user.Name = "Ada L."

err = ⟦+:db.SaveChanges(ctx)⟧
```

```sql marks title="Sends"
UPDATE "users" SET ⟦+:"name" = $1⟧, "updated_at" = $2
WHERE "users"."id" = $3
```

- Code can change fields anywhere, and nothing has to pass along which ones changed.
- If both requests change the same field, the last one wins. With an [`ant:"version"`](/lifecycle/optimistic-concurrency) field, the second save fails instead.

</Ant>

## Migrations

ant never changes your schema on its own. There is no auto-migrate, and `Open` doesn't touch the schema. `migrate diff` compares your structs with a stored snapshot and writes the difference as a plain SQL file, which you review before `migrate up` applies it. No database is needed to generate it. For an existing database, `migrate drift` lists every difference between your structs and the live schema until there are none.

Migrations run on PostgreSQL only. On the other databases ant reads and writes your existing tables, and your current migration tool keeps the schema. [Migrations](/migrations/overview) covers new projects and how ant compares with GORM's AutoMigrate, Atlas and sqlc. [Adopting a database](/migrations/adopting) covers existing ones.

## What it costs

ant keeps a copy of every row it loads, so `SaveChanges` can find what changed. On a 1000-row read, that makes ant 1.7 times slower than the same query with `NoTracking`, and uses 3 times the memory. Use `NoTracking` for lists, exports and reports; with it, ant read 1000 rows faster than GORM, Bun and ent in our runs.

Single-row reads and writes cost about the same in every library, because the round trip to the database is most of the time. ant allocates more than Bun and plain SQL on small queries.

[Benchmarks](/reference/benchmarks) has the full tables and how to run them.

## Limits

- **Some mistakes compile.** A field pointer from another model's probe, a pointer that isn't from a probe, and a `Find` key of the wrong type are refused when the query runs, not at build time. [antvet](/tooling/antvet) reports them in `go vet`. ent and sqlc catch these at build or generate time.
- **Go 1.27 or later.** ant uses generic methods, so it can't support older Go.
- **Pre-1.0.** The API can still change between releases.
- **Migrations are PostgreSQL only.** The other four databases get queries, writes, relations, tracking and transactions, and keep their current migration tool.
- **No down migrations.** To undo a change, write a new migration.
- **Tracking holds memory.** A tracker grows until it's discarded and serves one unit of work at a time, so use an `ant.Session` per request.
- **The last write wins** when two requests change the same field. Add an `ant:"version"` field to make the second save fail instead.
- **Probes are found by address.** ant pins each probe with `runtime.Pinner`, so its address stays fixed even if Go's collector ever moves objects.

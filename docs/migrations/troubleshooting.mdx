---
title: Troubleshooting
description: What each migration failure means, and what to do about it.
---

## A migration failed

It ran in a transaction, so none of it stuck, and later migrations didn't run. Fix the file and run `up` again. [Fill a new column from existing data](/migrations/generated-sql#fill-a-new-column-from-existing-data) shows this case and its fix.

```text
Error: ant: migration 0016_add_handle failed and was rolled back: ERROR: could not create unique index "people_handle_key" (SQLSTATE 23505)
  Key (handle)=() is duplicated.
```

## A no-transaction migration failed partway

Some of it may have run, so `up` refuses to continue. ant records such a file as failed before it starts, so one whose process was killed partway is `failed` too, with `it did not finish`, rather than pending, where `up` would run it again from the first statement. Check the database, then pick one.

- If you undid what ran, or the file can run again: fix the file, run `repair`, then `up`.
- If you finished it by hand: run `repair`, then `baseline <version>`.

## `applied migration was changed`

A file that has already run was edited. Put it back and make the change in a new migration. If the edit changes nothing, such as a comment, run `repair`. Line endings don't count as an edit.

```text
Error: ant: applied migration was changed: 0015_orders. Applied migrations must not change: put the file back, write a new migration, or run repair if the edit changes nothing
```

`status` shows the file as `changed`. After `repair`, it is `applied` again.

## `was applied as ..., a different migration`

The version ran under another name with other contents: two branches both wrote `0002`, a database ran the other branch's, and the file was renumbered after the merge. It is not an edit, so `repair` refuses it.

```text
Error: ant: applied migration was changed: 0002_add_ay was applied as 0002_add_bee, a different migration. If it was renumbered after a merge, give the file the next free number; if it is the same migration, name it 0002_add_bee again
```

A new name with the same contents is the same migration, and is no error.

## `has a BEGIN of its own`

The file runs in ant's transaction and holds its own `BEGIN`, `COMMIT` or `ROLLBACK`, which would end that transaction. Take them out, or put `-- ant:no-transaction` at the top. A `-- ant:no-transaction` below the first statement is refused the same way, since it would not be read; move it into the comments at the top. Both are checked before anything of the file runs. See [statements that refuse a transaction](/migrations/hand-written#statements-that-refuse-a-transaction).

## `no migrations folder at ...`

The versions folder isn't where the program looks, as when it runs from another directory or from an image built without its migrations. `up`, `status` and `baseline` refuse rather than apply nothing. Run it from the project's root, or set `Config.Dir`. `diff`, `adopt`, `check` and `drift` work without the folder.

## `no migration has version ...`

`up --to` and `baseline` name a version that no file has, as a typo would. Check `status` for the versions there are.

## `applied migration is missing`

A file that ran is gone. Put it back. For a Go migration, make sure the program imports the package that registers it. If the file is gone on purpose, `repair` forgets it.

## `drift` reports something you did on purpose

To keep it, add it to the models and run `snapshot`, or put it in `Config.Ignore`. Each line says what the database would need to do to match: `drop index people_nick_idx` means the database has an index the snapshot doesn't.

```text
The database differs from the snapshot. To match, it would need to:
  drop index people_nick_idx on people
  drop column people.nick
```

## `diff` stops on a rename

A `--rename` whose new name isn't a table or column in the models, or that the snapshot already has, writes nothing. The message lists the names that are new in the models:

```text
Error: ant: rename "users=peple": models have no table peple; new tables in the models: people
```

See [renames](/migrations/generated-sql#rename-a-column-or-table).

## `diff` refuses a name

PostgreSQL cuts a name over 63 bytes. `diff` says which one; give it a shorter name.

```text
Error: ant: index name "tickets_a_very_long_index_name_that_goes_well_beyond_the_limit_of_sixty_three_bytes" is 83 bytes, and postgres keeps only 63: give it a shorter one
```

## `script` refuses a no-transaction migration

`script` guards each migration with a check on the history table, which a migration without a transaction can't have. Use `script --plain`, or `up`. See [deploying](/migrations/deploying#hand-the-sql-to-someone-else).

## `diff` wrote something you do not want

Delete the file, and restore the snapshot.

```bash
git checkout migrations/versions/schema.snapshot.json
```

---
title: Joins
description: Follow relations, or join on any condition, across up to four models.
---

A join follows a relation, or any condition you give it. The result is typed by the models in it, and conditions and ordering can use any of them. `Select` turns each joined row into a value of your own.

## Join through a relation

`Join` follows a `*T` relation, and `JoinMany` follows a `[]T` one, giving one result per related row.

```go
rows, err := db.Posts.
	Join(&P.User).
	Where(ant.Eq(&U.Name, "Alice")).
	OrderBy(&P.Title).
	Select(func(p *Post, u *User) string { return u.Name + ": " + p.Title }).
	All(ctx)
// SELECT ... FROM "posts"
// JOIN "users" ON "posts"."user_id" = "users"."id"
// WHERE "users"."name" = $1
// ORDER BY "posts"."title"
```

```go
titles, err := db.Users.
	JoinMany(&U.Posts).
	Select(func(u *User, p *Post) string { return p.Title }).
	All(ctx)
// SELECT ... FROM "users" JOIN "posts" ON "users"."id" = "posts"."user_id"
```

:::tip[`Join` or `Include`?]

A join gives you one flat row per match, to project or filter on. To load whole models with their relations attached, use [`Include`](/relations/loading).

:::

## Keep rows with no match {#left-joins}

`LeftJoin` and `LeftJoinMany` keep rows with no match, and the missing side is `nil`.

```go
rows, err := db.Users.
	LeftJoinMany(&U.Posts).
	Select(func(u *User, p *Post) string {
		if p == nil {
			return u.Name + " has no posts"
		}

		return u.Name + ": " + p.Title
	}).
	All(ctx)
// SELECT ... FROM "users" LEFT JOIN "posts" ON "users"."id" = "posts"."user_id"
```

## Join on any condition

`JoinOn` needs no relation. The other model is a type argument.

```go
rows, err := db.Users.
	JoinOn[Post](ant.EqCol(&U.ID, &P.UserID), ant.Eq(&P.Published, true)).
	Select(func(u *User, p *Post) string { return p.Title }).
	All(ctx)
// SELECT ... FROM "users"
// JOIN "posts" ON "users"."id" = "posts"."user_id" AND "posts"."published" = $1
```

Conditions in the join put the filter in the `ON` clause. On a left join this matters: a published-only condition in `ON` keeps users with no published posts, and the same condition in `Where` drops them.

`LeftJoinOn`, `RightJoinOn` and `FullJoinOn` work the same way. `CrossJoin[Post]()` takes no condition and pairs every row with every row:

```go
pairs, err := db.Users.
	CrossJoin[Post]().
	Select(func(u *User, p *Post) string { return u.Name + "/" + p.Title }).
	All(ctx)
// SELECT ... FROM "users" CROSS JOIN "posts"
```

`JoinUsing[Post](&U.ID)` joins on a column both tables have, and is called on a query: `db.Users.Query().JoinUsing[Post](&U.ID)`.

`FULL JOIN` depends on the database: PostgreSQL, SQLite and SQL Server have it, MySQL and MariaDB don't. See [databases](/reference/databases).

## Three and four models

Chain joins, and each step can follow a relation of any model already in the query.

```go
type Comment struct {
	ID     int64
	PostID int64
	Text   string
	Post   *Post
}

var C = ant.Fields[Comment]()

rows, err := db.Comments.
	Join(&C.Post).Join(&P.User).
	Where(ant.Eq(&U.Name, "Ann")).
	Select(func(c *Comment, p *Post, u *User) string {
		return u.Name + "/" + p.Title + "/" + c.Text
	}).
	All(ctx)
// SELECT ... FROM "comments"
// JOIN "posts" ON "comments"."post_id" = "posts"."id"
// JOIN "users" ON "posts"."user_id" = "users"."id"
// WHERE "users"."name" = $1
```

## Join a table with itself

Each side of a self-join is its own row. The second copy gets an alias.

```go
pairs, err := db.Folders.
	Join(&F.Parent).
	Select(func(child, parent *Folder) string { return parent.Name + "/" + child.Name }).
	All(ctx)
// SELECT ... FROM "folders" JOIN "folders" AS "t1" ON "folders"."parent_id" = "t1"."id"
```

## Join a query

`JoinSub` joins the results of a query, so they can be narrowed first. Probes of the joined model refer to its columns.

```go
published := db.Posts.Where(ant.Eq(&P.Published, true))

rows, err := ant.
	JoinSub(db.Users.OrderBy(&U.Name), published, ant.EqCol(&U.ID, &P.UserID)).
	Select(func(u *User, p *Post) string { return p.Title }).
	All(ctx)
// SELECT ... FROM "users"
// JOIN (SELECT ... FROM "posts" WHERE "posts"."published" = $1) AS "posts"
//   ON "users"."id" = "posts"."user_id"
// ORDER BY "users"."name"
```

`LeftJoinSub` keeps rows with no match. To join a list held in memory, see [`ant.Values`](/queries/subqueries-and-sets#rows-held-in-memory).

## The newest rows per parent

A lateral join runs once per row, so it can read the top few rows for each parent, which a plain join can't do.

```go
newest := db.Posts.Where(ant.EqCol(&P.UserID, &U.ID)).OrderByDesc(&P.ID).Limit(2)

rows, err := ant.
	JoinLateral(db.Users.OrderBy(&U.Name), newest).
	Select(func(u *User, p *Post) string { return p.Title }).
	All(ctx)
// SELECT ... FROM "users"
// JOIN LATERAL (
//   SELECT ... FROM "posts"
//   WHERE "posts"."user_id" = "users"."id"
//   ORDER BY "posts"."id" DESC LIMIT $1
// ) AS "posts" ON 1 = 1
// ORDER BY "users"."name"
```

`LeftJoinLateral` keeps users with no posts. Lateral joins work on PostgreSQL and MySQL only. See [databases](/reference/databases).

A query runs when you call one of these. Which one you pick says how many rows you expect back.

## Get every matching row

`All` returns the rows as `[]*T`. No matches is an empty slice, not an error.

```go
users, err := db.Users.Where(ant.Gt(&U.Age, 18)).All(ctx)
// SELECT ... FROM "users" WHERE "users"."age" > $1
```

## Get the first row

`First` returns one row, or `ant.ErrNotFound`. Order the query to say which row is first.

```go
oldest, err := db.Users.OrderByDesc(&U.Age).First(ctx)
// SELECT ... FROM "users" ORDER BY "users"."age" DESC LIMIT $1

if errors.Is(err, ant.ErrNotFound) {
	return nil
}
```

## Get the one row that must exist

`Single` is for a lookup that should match exactly one row. It returns `ant.ErrNotFound` for none and `ant.ErrMultipleRows` for more than one.

```go
user, err := db.Users.Where(ant.Eq(&U.Email, "ada@example.com")).Single(ctx)
// SELECT ... FROM "users" WHERE "users"."email" = $1 LIMIT $2   -- $2 = 2
```

It asks for two rows so it can tell one from many.

## Find by primary key

`Find` returns the row with that key, or `ant.ErrNotFound`. For a composite key, use [`FindKey`](/models/keys#composite-keys).

```go
user, err := db.Users.Find(ctx, id)
// SELECT ... FROM "users" WHERE "users"."id" = $1 LIMIT $2
```

With tracking on, a `Find` for a row the context already tracks sends no query and returns the tracked instance, unsaved changes included.

## Stream a large result {#each}

`Each` is a Go iterator that yields rows one at a time, for results too big to hold in memory. `break` releases the connection.

```go
for user, err := range db.Users.OrderBy(&U.Name).Each(ctx) {
	if err != nil {
		return err
	}

	fmt.Println(user.Name)
}
// SELECT ... FROM "users" ORDER BY "users"."name"
```

If the query has a mistake, it arrives as the only item. `Each` yields values, so its rows aren't tracked, and it refuses `Include` with `ant.ErrIncludeInEach` because rows are still streaming in. To process a large result in batches with `Include`, use [`Chunk`](/queries/ordering-and-paging#chunks).

## Count and check

`Count` returns the number of matching rows. `Exists` and `DoesNotExist` answer a yes or no without fetching them.

```go
n, err := db.Users.Where(ant.Gt(&U.Age, 18)).Count(ctx)
// SELECT COUNT(*) FROM "users" WHERE "users"."age" > $1

found, err := db.Users.Where(ant.Eq(&U.Name, "Ada")).Exists(ctx)
// SELECT EXISTS (SELECT 1 FROM "users" WHERE "users"."name" = $1)

missing, err := db.Users.Where(ant.Eq(&U.Name, "Ada")).DoesNotExist(ctx)
```

`Count` honors `Limit`, `Offset` and `Distinct` by counting the rows of the limited query:

```go
n, err := db.Users.OrderBy(&U.Name).Limit(5).Count(ctx)
// SELECT COUNT(*) FROM (SELECT ... FROM "users" LIMIT $1) AS "ant_counted"
```

On a query built with `FromCTE` or `Recursive`, `Count` and `Exists` write the `WITH` at the start of the statement on every database, because SQL Server takes it nowhere else. See [CTEs](/queries/subqueries-and-sets#common-table-expressions).

## Read one column

`ant.Pluck` reads a single column into a slice of its Go type. It is the call for a dropdown or a list of ids.

```go
names, err := ant.Pluck(ctx, db.Users.Where(ant.Gte(&U.Age, 18)).OrderBy(&U.Name), &U.Name)
// SELECT "users"."name" FROM "users" WHERE "users"."age" >= $1 ORDER BY "users"."name"
```

With a pointer column, `NULL`s come back as `nil`:

```go
bios, err := ant.Pluck(ctx, db.Users.Where(), &U.Bio) // []*string
// SELECT "users"."bio" FROM "users"
```

## Load part of a row

`Column` and `Omit` load only some columns. The other fields keep their zero value, which is why these rows are never tracked: they can't be saved by mistake.

```go
names, err := db.Users.Column(&U.ID).Column(&U.Name).All(ctx)
// SELECT "users"."id", "users"."name" FROM "users"

small, err := db.Users.Omit(&U.Bio).All(ctx)
// SELECT "users"."id", "users"."created_at", "users"."updated_at", "users"."name", "users"."email", "users"."age" FROM "users"
```

For results in a shape of your own, see [projections](/queries/projections).

## Distinct values

```go
ages, err := db.Users.Column(&U.Age).Distinct().All(ctx)
// SELECT DISTINCT "users"."age" FROM "users"
```

## Skip the tracker

Results are tracked by default, so `SaveChanges` can see what you change. For reads you won't change, `NoTracking` skips the snapshot.

```go
users, err := db.Users.NoTracking().Where(ant.Gt(&U.Age, 18)).All(ctx)
```

`NoTrackingResolved` skips it too, but still gives each row a single instance, which helps when a read returns the same parent many times.

## One tracking context, one operation at a time

A tracked read hands out the same instance of a row to every query on the context, and `Include` writes related rows into it. So a context that tracks serves one operation at a time. A tracked read, `Find` included, claims the tracker, and a second one that starts before the first ends returns `ant.ErrConcurrentUse` instead of waiting.

Give each request or goroutine its own context with `ant.Session`. A context opened with `ant.WithTracking(false)` never claims, so it is safe to share.

```go
func handler(w http.ResponseWriter, r *http.Request) {
	db := ant.Session(shared) // its own tracker

	users, err := db.Users.Where(ant.Gt(&U.Age, 18)).All(r.Context())
	// ...
}
```

An `ant.Expr[V]` computes a value in SQL and knows its Go type. You can compare it, order by it, select it, or write it to a column.

## Use an expression in a query

```go
lower := ant.Lower(&U.Name)

users, err := db.Users.
	Where(lower.Eq("bob")).
	Order(lower.Desc()).
	All(ctx)
// SELECT ... FROM "users" WHERE LOWER("users"."name") = $1 ORDER BY LOWER("users"."name") DESC
```

## Columns and arithmetic

`ant.Col` turns a probe into an expression, and arithmetic stays typed.

```go
nextYear := ant.Col(&U.Age).Plus(1)

users, err := db.Users.Where(nextYear.Eq(18)).All(ctx)
// SELECT ... FROM "users" WHERE ("users"."age" + $1) = $2
```

| Method | Does |
| --- | --- |
| `.Plus`, `.Minus`, `.Times`, `.Div` | arithmetic with a value |
| `.Eq`, `.Ne`, `.Gt`, `.Gte`, `.Lt`, `.Lte` | compare with a value, giving a `Cond` |
| `.EqExpr`, `.GtExpr`, `.LtExpr` | compare with another expression |
| `.IsNull`, `.IsNotNull` | check for `NULL` |
| `.Asc`, `.Desc` | an ordering term |
| `.Filter(conds...)` | narrow an [aggregate](/queries/aggregates-and-grouping) |
| `.Over(window)` | run as a [window function](/queries/window-functions) |

## Built-in functions

```go
lower := ant.Lower(&U.Name)
upper := ant.Upper(&U.Name)
length := ant.Length(&U.Name)
fallback := ant.Coalesce(&U.Bio, new("none"))
sorted := ant.Collate(&U.Name, "C")

users, err := db.Users.Where(length.Gte(5)).Order(sorted.Asc()).All(ctx)
// SELECT ... FROM "users" WHERE LENGTH("users"."name") >= $1 ORDER BY "users"."name" COLLATE "C"
```

`Coalesce` takes the first value that isn't `NULL`. Order by it to sort rows with no bio as if they held a default:

```go
users, err := db.Users.Order(ant.Coalesce(&U.Bio, new("none")).Asc()).All(ctx)
// SELECT ... FROM "users" ORDER BY COALESCE("users"."bio", $1)
```

## CASE

`ant.Case` picks a value by condition. It is how you turn a number into a label inside the query.

```go
kind := ant.Case[string]().
	When(ant.Lt(&U.Age, 18), "minor").
	When(ant.Gt(&U.Age, 65), "senior").
	Else("adult")
// CASE WHEN "users"."age" < $1 THEN $2 WHEN "users"."age" > $3 THEN $4 ELSE $5 END
```

`Else` returns the finished `Expr[string]`. `End` leaves it open, as `Expr[sql.Null[string]]`, since a row that matches nothing is `NULL`. `WhenExpr` and `ElseExpr` take columns or other expressions as results.

To read the label, map it into a struct with [`Project`](/queries/projections):

```go
type Labeled struct {
	Name string
	Kind string
}

var L = ant.Fields[Labeled]()

kind := ant.Case[string]().
	When(ant.Lt(&U.Age, 18), "minor").
	When(ant.Gt(&U.Age, 65), "senior").
	Else("adult")

rows, err := ant.Project[Labeled](
	db.Users.Where(),
	ant.Into(&L.Name, &U.Name),
	ant.IntoExpr(&L.Kind, kind),
).All(ctx)
// SELECT "users"."name" AS "name",
//   CASE WHEN "users"."age" < $1 THEN $2 WHEN "users"."age" > $3 THEN $4 ELSE $5 END AS "kind"
// FROM "users"
```

## Call any database function

`ant.Func` calls a function by name, with the result type you state. Columns go in as expressions, and other values are bound.

```go
fixed := ant.Func[string]("REPLACE", ant.Col(&U.Name), "o", "0")
// REPLACE("users"."name", $1, $2)
```

## A SQL fragment

`ant.SQL` lets you write the expression yourself. Each `?` takes a column or a bound value, so a value never becomes part of the statement text. `ant.SQLCond` is the same, as a condition.

```go
label := ant.SQL[string]("? || ?", ant.Col(&U.Name), "/x")
// "users"."name" || $1

even := ant.SQLCond("? % ? = 0", ant.Col(&U.Age), 2)

users, err := db.Users.Where(even).All(ctx)
// SELECT ... FROM "users" WHERE ("users"."age" % $1 = 0)
```

The wrong number of arguments is an error.

:::danger[Never build the text from input]

The string is SQL, by design. Pass values as arguments, and keep the text a constant.

:::

---
title: Inspecting queries
description: See the SQL, the plan, and what a piece of code really writes.
---

Four ways to see what ant sends, from one query up to a whole unit of work.

## ToSQL

`ToSQL` returns a query's statement and arguments without running it. No database is needed.

```go
// spot-next-line
text, args, err := db.Users.Where(ant.Gt(&U.Age, 18)).OrderBy(&U.Name).Limit(5).ToSQL()
```

```sql
SELECT "users"."id", ... FROM "users" WHERE "users"."age" > $1 ORDER BY "users"."name" LIMIT $2
```

`args` is `[18 5]`. `ToSQLContext` applies [global filters](/lifecycle/global-filters) from a context. `UpdateSQL` and `DeleteSQL` do the same for writes.

## Explain

`Explain` returns the database's query plan as text. Use it to check that an index is used.

```go
// spot-next-line
plan, err := db.Users.Where(ant.Gt(&U.Age, 18)).Explain(ctx)
```

## Debug

`Debug` logs one query's SQL and values through slog's default logger. It shows values, so take it out before committing.

```go
// spot-next-line
users, err := db.Users.Where(ant.Eq(&U.Name, "Alice")).Debug().All(ctx)
```

## DryRun

`ant.DryRun` runs your code in a transaction, returns every statement it ran, and rolls back. Use it to see what a unit of work writes. Sequences still move on, and anything the function does outside the database still happens.

```go
// spot-start
statements, err := ant.DryRun(ctx, db, func(tx *AppDB) error {
	return tx.Users.Insert(ctx, &User{Name: "Temp", Email: "temp@example.com"})
})
// spot-end

for _, s := range statements {
	fmt.Println(s.SQL)
}
```

---
title: Logging
description: Statements through log/slog, with values kept out by default.
---

`ant.WithLogger` logs every statement through `log/slog`. Values stay out of the logs unless you ask for them.

## Log statements

```go
logger := slog.New(slog.NewTextHandler(os.Stderr, &slog.HandlerOptions{
	Level: slog.LevelDebug,
}))

// spot-next-line
db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn, ant.WithLogger(logger))
```

Each line carries the SQL, the duration and the number of arguments. Statements log at debug, slow ones at warning, and failures at error. Set the handler's level to debug to see them all.

## Slow queries

With `SlowThreshold`, statements at or over the limit log at warning. Without it, none do.

```go
db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn,
	// spot-next-line
	ant.WithLogger(logger, ant.SlowThreshold(200*time.Millisecond)),
)
```

## Log values

`ant.LogValues` adds the argument values to each line. Use it in development only, since values can be passwords or personal data.

```go
db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn,
	// spot-next-line
	ant.WithLogger(logger, ant.LogValues()),
)
```

## Keep a column out of the logs

`.Sensitive()` marks a column so its value is never logged, even with `LogValues`, on inserts, updates, `Set` and conditions. It logs as `[redacted]`.

```go
type Account struct {
	ID       int64
	Password string
}

func (Account) Configure(b *ant.ModelBuilder[Account]) {
	// spot-next-line
	b.Column(&A.Password).Sensitive()
}

var A = ant.Fields[Account]()
```

{/*
```go
var logger *slog.Logger
```
*/}

:::warning[Limits]

`ant.SQL` arguments are not covered by `.Sensitive()`, because ant cannot tell which column they belong to. A database error's message can also quote a value, so do not return `err.Error()` to users.

:::

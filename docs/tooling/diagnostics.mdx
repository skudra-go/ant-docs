---
title: Diagnostics
description: Warnings about N+1 patterns, slow requests, and row explosions.
---

Diagnostics warn about patterns that no single query shows: the same statement run in a loop, a request that spends too long in the database, a join that multiplies rows. They count within a scope, usually one web request, and cost a little per statement.

## Turn it on

```go
db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn,
	// spot-start
	ant.WithDiagnostics(ant.Diagnostics{
		RepeatLimit: 10,
		Budget:      500 * time.Millisecond,
		Alert: func(ctx context.Context, a ant.Alert) {
			slog.Warn("database", "kind", a.Kind, "message", a.Message, "sql", a.SQL)
		},
	}),
	// spot-end
)
```

`RepeatLimit` and `Budget` are limits for each scope. The default `Alert` logs through `slog`.

## Start a scope for each request

`ant.Watch` returns a context that starts counting. Without a scope, repeats and budgets are not counted. Wrap each request in middleware:

```go
func middleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// spot-next-line
		next.ServeHTTP(w, r.WithContext(ant.Watch(r.Context())))
	})
}
```

## What it reports

| `Kind` | Means |
| --- | --- |
| `repeated` | One statement ran more than `RepeatLimit` times in a scope, which is what an N+1 loop looks like |
| `budget` | Statements together took longer than `Budget`, which a slow-query log misses when each one is fast |
| `cartesian` | A query joined two to-many relations, which multiplies rows. This reports with or without a scope |

A field named `ID` is the primary key. An integer key is generated by the database, and the new value is copied back onto your struct.

## Use ID as the key

```go
type Ticket struct {
	// spot-next-line
	ID    int64
	Title string
}

ticket := &Ticket{Title: "One"}

err := db.Tickets.Insert(ctx, ticket)
// INSERT INTO "tickets" ("title") VALUES ($1) RETURNING "id"

// spot-next-line
fmt.Println(ticket.ID) // set by the database

found, err := db.Tickets.Find(ctx, ticket.ID)
// SELECT ... FROM "tickets" WHERE "tickets"."id" = $1 LIMIT $2
```

A zero integer key means "assign me one". This is the only place ant reads a zero as "not set" without a tag. A non-zero key is written as given, even on a generated column, so imported rows keep their IDs.

```go
// spot-next-line
imported := &Ticket{ID: 500, Title: "Imported"}

err := db.Tickets.Insert(ctx, imported)
// INSERT INTO "tickets" ("id", "title") VALUES ($1, $2)
```

## Use another column as the key

`b.Key` replaces the convention. An `ID` field on the same model then becomes an ordinary column.

```go
type Country struct {
	ID   int64
	Code string
}

func (Country) Configure(b *ant.ModelBuilder[Country]) {
	// spot-next-line
	b.Key(&C.Code)
}

var C = ant.Fields[Country]()

// spot-next-line
latvia, err := db.Countries.Find(ctx, "LV")
// SELECT ... FROM "countries" WHERE "countries"."code" = $1 LIMIT $2
```

## Supply the key yourself

`NotGenerated` says the application always gives the key, so a zero is a real value and is written as it is.

```go
type Seat struct {
	Number int
	Row    string
}

func (Seat) Configure(b *ant.ModelBuilder[Seat]) {
	// spot-next-line
	b.Key(&S.Number).NotGenerated()
}

var S = ant.Fields[Seat]()

err := db.Seats.Insert(ctx, &Seat{Number: 0, Row: "A"})
// INSERT INTO "seats" ("number", "row") VALUES ($1, $2) -- $1 = 0
```

## String and UUID keys

Keys that aren't integers are never generated, and an empty one is written as it is. A named type works as a key, and a plain string finds it.

```go
type Slug string

type Page struct {
	ID    Slug
	Title string
}

// spot-start
err := db.Pages.Insert(ctx, &Page{ID: "home", Title: "Home"})
// INSERT INTO "pages" ("id", "title") VALUES ($1, $2)

home, err := db.Pages.Find(ctx, "home")
// spot-end
```

## Generate the key in Go

`ant.GenerateKey` fills in a zero key just before the insert. A key you supply is kept. If the insert fails, the generated key is cleared from the struct again, so a retry makes a new one.

```go
type Order struct {
	ID    string
	Total int
}

func (Order) Configure(b *ant.ModelBuilder[Order]) {
	// spot-next-line
	ant.GenerateKey(b, &O.ID, ids.UUID)
}

var O = ant.Fields[Order]()

order := &Order{Total: 5}

err := db.Orders.Insert(ctx, order)
// INSERT INTO "orders" ("id", "total") VALUES ($1, $2)
// -- $1 = 01a1bbb9-b230-7eea-baf0-d1429fddc54f
```

The `ids` package has `ids.UUID` (version 7) and `ids.ULID`. Both sort by creation time, so new rows land at the end of an index instead of scattering across it. For snowflake integers:

```go
// spot-next-line
flakes, err := ids.NewSnowflake(1) // the node number

next := flakes.Next()
```

## Composite keys

`CompositeKey` spans several columns. `FindKey` takes the parts in the order declared. Tracking, `Reload` and `Remove` use the whole key.

```go
type Grant struct {
	UserID int64
	Scope  string
	Level  int
}

func (Grant) Configure(b *ant.ModelBuilder[Grant]) {
	// spot-next-line
	b.CompositeKey(ant.F(&G.UserID), ant.F(&G.Scope))
}

var G = ant.Fields[Grant]()

// spot-next-line
grant, err := db.Grants.FindKey(ctx, int64(1), "write")
// SELECT ... FROM "grants"
// WHERE "grants"."user_id" = $1 AND "grants"."scope" = $2 LIMIT $3

grant.Level = 3

err = db.SaveChanges(ctx)
// UPDATE "grants" SET "level" = $1 WHERE "grants"."user_id" = $2 AND "grants"."scope" = $3

err = ant.Remove(ctx, db, grant)
err = db.SaveChanges(ctx)
// DELETE FROM "grants" WHERE "grants"."user_id" = $1 AND "grants"."scope" = $2
```

These errors come back from a composite key:

| Call | Error |
| --- | --- |
| `Find` (it takes one key value) | `ant.ErrNoKey` |
| `FindKey` with the wrong number of parts | `ant.ErrKeyType` |
| `FindKey` with no such row | `ant.ErrNotFound` |
| `SaveChanges` after changing part of a tracked key | `ant.ErrKeyChanged` |

To fetch many rows by composite key, use [`InTuples`](/queries/conditions#match-pairs-of-values).

### Times in a key

A `time.Time` in a key is identified as the instant, in UTC, to the microsecond. A key given in another zone finds the row already tracked, and a row read back from the database is the instance you have. Two keys less than a microsecond apart are one row to the tracker, even where SQL Server or SQLite could store them as two.

```go
type Reading struct {
	At    time.Time
	Value int
}

func (Reading) Configure(b *ant.ModelBuilder[Reading]) {
	// spot-next-line
	b.Key(&R.At).NotGenerated()
}

var R = ant.Fields[Reading]()

at := time.Date(2026, 1, 1, 12, 0, 0, 0, time.FixedZone("CET", 3600))

err := db.Readings.Insert(ctx, &Reading{At: at, Value: 1})

// spot-next-line
same, err := db.Readings.Find(ctx, at.UTC()) // the tracked row, not a second copy
```

## Sequences

A column can draw from a named sequence, which migrations create.

```go
func (Invoice) Configure(b *ant.ModelBuilder[Invoice]) {
	// spot-next-line
	b.Column(&I.Number).Sequence("invoice_numbers", ant.StartAt(1000), ant.IncrementBy(10))
}
```

## Models without a key

A model with no `ID` field has no key. It inserts and queries like any other, and `Find`, `DeleteByID` and `Reload` return `ant.ErrNoKey`. `b.NoKey()` does the same for a model whose `ID` column isn't unique, such as an event log.

```go
type LogLine struct {
	ID   int64
	Text string
}

func (LogLine) Configure(b *ant.ModelBuilder[LogLine]) {
	// spot-next-line
	b.NoKey()
}

err := db.Logs.Insert(ctx, &LogLine{Text: "x"})
// INSERT INTO "log_lines" ("id", "text") VALUES ($1, $2) -- $1 = 0
```

With `NoKey`, `ID` is an ordinary column, so it is written as given.

:::tip[The wrong key type]

`Find` can't tie its key type to the model at compile time. `db.Users.Find(ctx, "1")` compiles, and returns `ant.ErrKeyType` when it runs. An untyped number fits any integer key.

:::

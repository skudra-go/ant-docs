title: Defining models
description: Structs as models, ant.Base, naming conventions, and how to override them.
---

A model is a Go struct. It needs no base type, no tags and no generated code. Exported fields are columns, and the model is registered by listing it in your database struct.

## A model

```go
// spot-start
type Article struct {
	ID    int64
	Title string
	Views int
}
// spot-end

type BlogDB struct {
	ant.Context
	Articles ant.Table[Article]
}

var A = ant.Fields[Article]()
```

This maps to the table `articles`, with `id` as a primary key the database generates. `Open` reads the models in the struct, and fails at startup if one can't be mapped. See [keys](/models/keys) for other primary keys.

## Add IDs and timestamps with ant.Base

`ant.Base` holds `ID`, `CreatedAt` and `UpdatedAt`. Embed it when a table wants all three.

```go
type Article struct {
	// spot-next-line
	ant.Base
	Title string
}

article := &Article{Title: "Hello"}

err := db.Articles.Insert(ctx, article)
// INSERT INTO "articles" ("created_at", "updated_at", "title") VALUES ($1, $2, $3) RETURNING "id"

// spot-next-line
fmt.Println(article.ID, article.CreatedAt, article.UpdatedAt) // all filled in
```

`ant.Base` is optional and has no special status. Any model with a `time.Time` field named `CreatedAt` or `UpdatedAt` gets the same [timestamps](/lifecycle/timestamps).

## Table and column names

ant derives names from Go names.

| Go | Database |
| --- | --- |
| `type OrderItem` | table `order_items` |
| `UserID` | column `user_id` |
| `HTTPPort` | column `http_port` |
| `ID` | primary key `id` |

Table names are plural. ant adds `s`, or `es` after `s`, `x`, `ch` and `sh`, and turns a consonant followed by `y` into `ies`. That gives `categories` for `Category`, and also `persons` for `Person` and `childs` for `Child`. Set `b.Table` when the result reads wrong.

## Rename a column or a table

A tag renames a column. `Configure` renames a table.

```go
type Device struct {
	ID   int64
	// spot-next-line
	Name string `ant:"column=display_name"`
}

func (Device) Configure(b *ant.ModelBuilder[Device]) {
	// spot-next-line
	b.Table("hardware")
}
```

Use this to map a model onto a table that already exists with names of its own.

## Leave a field out

A field tagged `ant:"-"`, and any unexported field, is not a column. ant never reads, writes or queries it. Use it for values you compute or cache on the struct.

```go
type Session struct {
	ID     int64
	Token  string
	// spot-start
	Cached string `ant:"-"`
	secret string
	// spot-end
}
```

## Change the naming rules

`ant.WithNaming` replaces the conventions for every model, which suits an existing database with its own style. A nil function keeps the default for that part, and a name you set explicitly stays as you set it.

```go
db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn,
	// spot-start
	ant.WithNaming(ant.Naming{
		Table:  func(name string) string { return "tbl_" + name },
		Column: func(name string) string { return "col_" + name },
	}),
	// spot-end
)
```

`ant.WithConvention` runs a rule on every model as it is configured. This one gives every string column a length of 100. A model's `Configure` method runs after the rule and can override it.

```go
rule := func(m *ant.ModelConvention) {
	for _, f := range m.Fields() {
		if f.Type.Kind() == reflect.String {
			// spot-next-line
			f.SetLength(100)
		}
	}
}

db, err := ant.Open[AppDB](ctx, postgres.Dialect, dsn, ant.WithConvention(rule))
```

:::warning[Set once per process]

ant reflects each model once per process, so naming and conventions are global. They come from the first `Open`.

:::

---
title: Field roles
description: Tags that decide how a field is read and written.
---

Tags combine with commas, as in `ant:"default='new',immutable"`.

## All the tags

| Tag | Means |
| --- | --- |
| `ant:"-"` | Not a column |
| `ant:"column=name"` | Use this column name |
| `ant:"unique"` | A unique constraint, used by migrations |
| `ant:"default=expr"` | Leave a zero value to the column's default. [Details](/models/nullable-and-defaults#database-defaults) |
| `ant:"readonly"` | Filled by the database, never written |
| `ant:"writeonly"` | Written, never read |
| `ant:"immutable"` | Written on insert, never changed by `SaveChanges` |
| `ant:"computed"` | Filled by `Query.With`, no column |
| `ant:"version"` | [Optimistic concurrency](/lifecycle/optimistic-concurrency) counter |
| `ant:"token"` | Optimistic concurrency, with a value you manage |
| `ant:"embedded"`, `ant:"embedded,prefix=x_"` | [Flatten a struct](/models/embedded-and-mixins) into columns |

## Read a value the database generates

`readonly` suits generated columns and trigger-set values. ant leaves the column out of every write and copies the value back after an insert.

```go
type Account struct {
	ID    int64
	Email string
	// spot-next-line
	Slug  string `ant:"readonly"` // GENERATED ALWAYS AS (lower(email))
}

account := &Account{Email: "A@X"}

err := db.Accounts.Insert(ctx, account)
// INSERT INTO "accounts" ("email") VALUES ($1) RETURNING "id", "slug"

fmt.Println(account.Slug) // "a@x"
```

A column declared with `b.Column(&...).Generated(expr)` is read-only without the tag.

## Keep a value out of query results

`writeonly` suits a value that must never be read back, such as a password hash. The column is written and left out of every select.

```go
type Account struct {
	ID       int64
	// spot-next-line
	Password string `ant:"writeonly"`
}

// spot-start
found, err := db.Accounts.Find(ctx, id)
// SELECT "accounts"."id" FROM "accounts" WHERE "accounts"."id" = $1 LIMIT $2

fmt.Println(found.Password) // empty: never read
// spot-end
```

`SaveChanges` writes a changed value, and an explicit `Update` can set it.

## Write a value once

`immutable` writes the field on insert. `SaveChanges` ignores a later change: nothing is written and the entity is not marked modified.

```go
type Account struct {
	ID        int64
	// spot-next-line
	CreatedBy string `ant:"immutable"`
}

account.CreatedBy = "someone else"

// spot-next-line
changed, err := db.HasChanges(ctx) // false
```

In v0.2.0 the tag guards `SaveChanges` only, and an explicit `db.Accounts.Where(...).Update(ctx, ant.Set(&Accounts.CreatedBy, "x"))` still writes the column. From the next release, a bulk `Update`, an upsert's `DoUpdate` or `Set`, a merge's `WhenMatched` and `UpdateMany` refuse an immutable, readonly or computed field with an error naming it ([#62](https://github.com/skudra-go/ant/issues/62)).

## Computed

`computed` has no column. `Query.With` fills it from an expression; without `With` it stays empty.

```go
type Writer struct {
	ID           int64
	Name         string
	Articles     []Article
	// spot-next-line
	ArticleCount int64 `ant:"computed"`
}

type Article struct {
	ID       int64
	WriterID int64
}

var Writers = ant.Fields[Writer]()

writers, err := db.Writers.
	// spot-next-line
	With(&Writers.ArticleCount, ant.CountRelated(&Writers.Articles)).
	All(ctx)
// SELECT "writers"."id", "writers"."name",
//   (SELECT COUNT(*) FROM "articles" AS "ant_related" WHERE "ant_related"."writer_id" = "writers"."id") AS "article_count"
// FROM "writers"
```

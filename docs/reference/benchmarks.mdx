ant next to GORM 1.31, Bun 1.3, ent 0.14 and plain `database/sql`, doing the same work on one PostgreSQL 17. Plain SQL stands in for sqlc, whose generated code is a query string and a `Scan`. `TestSameQuery` in the same module checks that all four libraries return the same rows for the query on [Why ant](/why-ant#one-query-four-libraries).

## Setup

[`tools/compare`](https://github.com/skudra-go/ant/tree/main/tools/compare) runs the same operations in each library against PostgreSQL 17, on one machine: a Ryzen 5 3600, with the database in Docker on WSL2.

- Each number is the median of 10 runs. A run repeats the operation for a second, hundreds to thousands of times, and averages it.
- Every number includes the round trip to the database, which is most of the time on small queries.
- Commits don't wait for the disk (`synchronous_commit=off`), so disk speed doesn't drown out the libraries on writes.
- Plain SQL is the baseline: a hand-written query and `Scan`, which is what sqlc generates.
- ant runs with change tracking (its default) and with `NoTracking`.

Green is the best library in each row.

## What the numbers say

- Small queries cost about the same in every library.
- ant keeps a copy of each loaded row so [`SaveChanges`](/tracking/save-changes) can find changes. That makes 1000 rows 1.7 times slower and 3 times the memory. With [`NoTracking`](/queries/reading-rows#skip-the-tracker), ant reads them fastest.
- Bun puts insert values into the SQL text, so the driver prepares every insert as a new statement. `default_query_exec_mode=simple_protocol` in the DSN brings it to 452 µs.
- ent's update reads the row back in a transaction, so load, edit and save takes four statements instead of two.

## Building queries

`tests/benchmarks` measures what ant adds with no database involved:

| Operation | Time | Allocations |
| --- | --- | --- |
| Resolving a field pointer | 22 ns | 0 |
| Building and rendering a query with two conditions, an order, and a limit | 7.3 µs | 78 |

Budgets in `tests/benchmarks/allocs_test.go` fail a test if these grow.

Rendering takes a few microseconds, against a few hundred for the round trip, which is why ant doesn't cache rendered SQL: a cache key would cost about what it saves, and pgx already caches prepared statements per connection.

## Run them yourself

```sh
make db-up DATABASES=postgres   # from the ant repo root
cd tools/compare
go test -run '^$' -bench . -benchmem -count 10 | tee new.txt
go run golang.org/x/perf/cmd/benchstat@latest new.txt
```

title: Compatibility
description: Supported Go and database versions, what counts as the API, and how to upgrade.
---

ant hasn't reached 1.0, so anything can change between releases. Each release's [release notes](https://github.com/skudra-go/ant/releases) list its breaking changes.

## Go

ant needs Go 1.27 or later, because its API uses generic methods. Each release supports the two newest Go versions.

| Feature | Since | Used for |
| --- | --- | --- |
| `iter.Seq2` | Go 1.23 | Streaming with `Each` |
| `new(expr)` | Go 1.26 | Nullable values, as in `user.Bio = new("text")` |
| Generic methods | Go 1.27 | `Join[J]`, `Include[R]`, `Select[R]` in fluent chains |
| Field selectors as struct literal keys | Go 1.27 | `User{ID: 1}` for fields promoted from `ant.Base` |

## Databases

| Database | Status |
| --- | --- |
| PostgreSQL 13 to 18 | Supported: the whole suite passes on each, as of 2026-11-01 |
| MySQL 8.4, MariaDB 11.8, SQLite (modernc 1.61), SQL Server 2022 | Queries and writes: the conformance and concurrency suites pass. No migrations |

`MERGE` needs PostgreSQL 15. Everything else works from 13. PostgreSQL 12 and older are out of support upstream and untested here. The comments in each dialect name the oldest versions expected to work, from their documentation, but only the versions above have been run.

ant runs on the `pgx` driver through `database/sql`. `pgxext` needs pgx. See [databases](/reference/databases) for what each database lacks.

## Breaking changes so far

The latest release is v0.6.0. Before it came v0.1.0, v0.2.0, v0.3.0, v0.3.1, v0.3.2, v0.4.0, v0.5.0 and v0.5.1.

### v0.6.0

The JSON of ant's own structs changes, and two errors change shape:

| Before | Now |
| --- | --- |
| `ant.Base` encoded as `{"ID":1,"CreatedAt":...,"UpdatedAt":...}` | `{"id":1,"createdAt":...,"updatedAt":...}`. `ant.Page` is `items`, `total`, `number`, `size`, and `ant.CursorPage` `items`, `next`. `postgres.Point`, `postgres.Partition` and `metrics.Sample` are camelCase too. Old keys still decode. To keep sending them, see [ant.Base in JSON](/models/defining-models#base-json) |
| A JSON column holding one of those structs matched conditions on its old keys | Rows written before keep the old keys until written again, so `JSONContains` with the new keys misses them. See [JSON written before v0.6.0](/models/custom-types#json-keys-before-v060) |
| A write that failed field rules returned the first failure, an `*ant.ValidationError` | It joins one per failing field, even for one. `errors.As` finds the first, and `err.(*ant.ValidationError)` never matches. See [read the error](/lifecycle/validation#read-the-error) |
| `drift` left out `b.View` models | It fails on a missing view, or a column the model reads that the view lacks. See [drift](/migrations/commands#look-at-the-database) |

The rest are additions and fixes:

- `ids.UUIDv7[uuid.UUID]` fills a `uuid.UUID` key, a `uuid` column on PostgreSQL. See [keys](/models/keys#generate-the-key-in-go) and [a UUID key on every model](/models/keys#a-uuid-key-on-every-model).
- Joins and projections have `Count`, `Exists`, `ToSQL`, `ToSQLContext` and `Debug`, and `Debug` logs every `SELECT` a query runs. See [count joined rows](/queries/joins#count-joined-rows).
- `InsertFrom` takes `ant.WithConflict`. See [skip rows the target already has](/writing/bulk#insert-from-with-conflict).
- `After` pages a column that can be NULL once its order says `NullsFirst` or `NullsLast`. See [page a column that can be NULL](/queries/ordering-and-paging#cursor-nulls).
- `diff --rename item_status.banned=blocked` renames an enum value in place. `drift` lists the types the models use and don't create, and `db-show` lists materialized views. See [rename an enum value](/migrations/generated-sql#rename-an-enum-value).
- `Explain` works on MySQL, MariaDB and SQLite, and plans `IncludeJoined`'s join. See [Explain](/tooling/inspecting-queries#explain).
- On SQLite, `ForUpdate` and `ForShare` work in a writable transaction on a `_txlock=immediate` DSN. See [row locks](/reference/databases#row-locks).
- [antvet](/tooling/antvet#queries-built-up-in-a-variable) follows a query built up in a variable.
- `IncludeJoined` applies the relation's `Where`, `Morph` type and `Latest` or `Oldest`. On SQL Server an ordered subquery, and `Distinct` with paging, no longer fail. `Find` after a bulk delete reads the row again. Retyping a `bool` column to a number, or back, migrates. `Exists` honours `Distinct` and `Offset`. Monthly partitions are found by their bounds. Errors for a field of the wrong model or kind name the field.

### v0.5.1

A SQLite DSN must choose `busy_timeout` and `_txlock` as well as `foreign_keys`, as in `_pragma=foreign_keys(1)&_pragma=busy_timeout(5000)&_txlock=immediate`, or `ant.Open` refuses it. `busy_timeout(0)` and `_txlock=deferred` keep the driver's defaults on purpose. See [the DSN settings](/reference/databases#import-a-driver).

- Field rules skip a zero `default=` field on insert, where the database fills it, and still check it on update and `Upsert`. See [fields the database fills](/lifecycle/validation#fields-the-database-fills).
- A row added to a scoped relation gets the values of the scope's `Eq` conditions. See [add to a scoped relation](/relations/advanced#add-to-a-scoped-relation).
- On SQLite, `MinOf`, `MaxOf` and the other aggregates of a time read into a time field.
- `drift` reports a serial column that draws from another sequence than the models'.
- antvet reports a field pointer that isn't a probe in `Latest`, `Oldest`, `Load` and `Recursive`.

### v0.5.0

Code that filters on nullable columns, or writes from a hook, will notice these:

| Before | Now |
| --- | --- |
| `Ne`, `NotIn` and `Not(Eq(...))` with a value left out the rows where a nullable column is NULL | They match them: `bio <> $1 OR bio IS NULL`. `Gt`, `Lt` and `Not(Gt(...))` still never match NULL. See [NULL](/queries/conditions#null) |
| `OrderBy`, `Gt` to `Between`, `Sum`, `Inc` and the other helpers took only `ant.Ordered` or `ant.Number` fields | They take a field of any type, so nullable, `uuid.UUID`, `decimal.Decimal` and `ant.DeletedAt` fields compile, and the database checks the column. `ant.Ordered` and `ant.Number` are deprecated |
| A query or write in a hook through another context, such as a global `db`, ran outside the write's transaction | The hook's `ctx` is bound to the transaction, as by the new `ant.InTx`, so it runs there and rolls back with the write. See [write from a hook](/lifecycle/hooks-and-observers#write-from-a-hook) |
| An entity read with `With` on a session wasn't tracked, so its changes were never saved | It is tracked. Its computed fields are never written |
| Replacing or clearing a loaded has-one kept the old row | It deletes the old row, or clears its foreign key if that is nullable. See [replace or clear a has-one](/tracking/changing-relations#replace-a-has-one) |

The rest are fixes, refusals of what used to fail later, and additions:

- A comparison with a nil pointer, such as `Gt` or `Between`, matches nothing, as in SQL. Only `Eq`, `Ne` and `In` turn nil into `IS NULL`.
- `Inc` on a nullable column counts a NULL from 0, and a step with a fraction on an integer field is refused.
- `ant.Project` reads a NULL from a left join, or from an aggregate over no rows, into a plain field as its zero value, where it failed. Wrap the expression in the new `ant.Nullable` and use an `sql.Null[V]` field to keep the NULL. See [NULL in a plain field](/queries/projections#null-in-a-plain-field).
- Code that holds `db`, such as a repository, runs in a transaction when given `ctx := ant.InTx(ctx, tx)`. See [code that holds db](/transactions#code-that-holds-db).
- Inserting a `uuid.UUID` or `string` key at its zero value returns the new `ant.ErrZeroKey`, where it was written as it was. See [string and UUID keys](/models/keys#string-and-uuid-keys).
- `ant.DeletedAt` encodes to JSON as `null` or a time, where it wrote `{"V": ..., "Valid": ...}`. It decodes all three. See [in JSON](/lifecycle/soft-deletes#json).
- On MySQL, MariaDB, SQLite and SQL Server, `ant.Open` refuses a slice, map or plain struct field with `ant.ErrNoColumnType`, including a type defined as `time.Time`, where the first write failed. It also refuses a `*ant.Table[T]` field, which panicked on first use. See [what Open refuses](/models/defining-models).
- Errors say what to write instead: a GORM tag such as `primaryKey` or `size:100` names ant's spelling, a relation with no foreign key names the fields ant looked for, and `ant.Open[*AppDB]` says to give the struct type. A table that doesn't exist gives `ant.SQLState(err) == "42P01"` on every database, with a hint to create it. See [errors](/tooling/errors).
- `FieldRef.Asc` and `FieldRef.Desc` order by a column chosen at run time. See [sort from a request](/queries/ordering-and-paging#sort-from-a-request).
- [antvet](/tooling/antvet) reports a change saved through a context that did not load the entity, which `SaveChanges` leaves out.

### v0.4.0

It changes how tracking starts, which most code that saves will notice:

| Before | Now |
| --- | --- |
| `ant.Open` returned a context that tracked | It doesn't track. `SaveChanges`, `ant.Add`, `ant.Attach`, `ant.MarkModified`, `ant.Remove` and `ant.TrackGraph` on it return `ant.ErrNoTracking`. Save through `ant.Session(db)`, which tracks. `ant.WithTracking(true)` on `Open` gives the old root, for a script |
| `ant.Session(db)` of a root opened with `WithTracking(false)` didn't track | A session tracks unless given `WithTracking(false)` |
| A rolled-back transaction left what it loaded in the tracker | A rollback forgets what its transaction began tracking |

On PostgreSQL, standard Go types take PostgreSQL's own column, and ant reads them back: `time.Duration` is `interval`, `net.IP` and `netip.Addr` are `inet`, `netip.Prefix` is `cidr`, `json.RawMessage` and a map with string keys are `jsonb`, `decimal.Decimal` is `numeric`, and a plain slice is an array, as `[]string` is `text[]`. A `time.Duration` was `bigint`, and a `net.IP` and a `json.RawMessage` were `bytea`, so the next `diff` of tables ant made converts those columns and their values. `.Type("bigint")` on a column keeps it as it is. See [columns made by earlier releases](/migrations/models-to-tables#columns-made-by-earlier-releases).

The rest of the changes are refusals of what ant used to misread, and fixes:

- `ant.Open` resolves every relation and refuses an unknown tag key, a flag key with a value, two fields on one column, `[]*Post`, an embedded `*Base`, func and chan fields, a many-to-many with no `Through` or with one column for both sides, and a SQLite DSN that doesn't set `foreign_keys` (from v0.5.1, also `busy_timeout` and `_txlock`). It reports every broken model at once.
- An update reads back `readonly` columns, an after hook's edit to its entity is saved by the next `SaveChanges`, an upsert's update writes the zero a `default` field holds, and an upsert repeats a partial unique index's condition.
- `ant.SchemaOf` takes options, and `migrate.Config.Options` passes the application's to the migrate program. `ant.ErrNoTracking` and `schema.Repartition` are new.
- Migrations refuse a file with its own `BEGIN` or `COMMIT` that runs in ant's transaction, a `-- ant:no-transaction` below the first statement, a missing versions folder, `up --to` an unknown version, and `baseline` with no version when more than one migration is left. `repair` refuses a version applied as another migration, and `diff` and `check` a snapshot written for a file that is gone. `status --check` fails while anything waits.
- Generated SQL: a new required foreign key column is added `NULL`, then `SET NOT NULL`; a foreign key column takes its target's type; enum and sequence names are quoted where columns use them; two default names that collide are refused; a concurrent index build drops a leftover first; partitioning changes are reported. `adopt` leaves out `OWNER TO`, `GRANT` and `REVOKE`.
- `IncludeJoined` and a projection with a `LeftJoin` read a joined side's `netip.Addr`, slices and `[16]byte`, which failed with `unsupported Scan`. `Avg` and `AvgOf` of a `time.Duration` read an `interval`'s average as nanoseconds.

### v0.3.2

No exported name changed or went away. It adds `ant.ErrNestedIsolation`, `pgxext.ErrInTx`, `metrics.Operation` and JSON decoding for `secure.Value`. Some behaviour changed, mostly where ant used to misread something without a word and now refuses it:

- `ant.Open` refuses a MySQL or MariaDB DSN without `parseTime=true`, a `version` field that is not a signed integer, and two models that reach one table by convention.
- Two relations to the same model, guessed onto one foreign key, are `ant.ErrNoForeignKey` until one names its key.
- A negative `Limit` or `Offset` is an error, and `ant.SQL` or `ant.SQLCond` with arguments needs one per `?`. `Raw` refuses two result columns for one field.
- `After` returns `ant.ErrCursor` for an ordering column that can hold `NULL`, and for a query with its own `Limit` or `Offset`. `Page`, `Chunk` and `ChunkByKey` read inside a query's `Limit` and `Offset`.
- `Upsert` runs the validation rules, `Validate`, `BeforeInsert` and `AfterInsert`. A soft delete and `Restore` stamp `UpdatedAt` and move a version on.
- Options on a `Tx` nested in another hold, so a nested `ant.ReadOnly()` is `ant.ErrUnsupported` off PostgreSQL. `pgxext.Copy` and `Batch.Send` refuse a transaction's context.
- A time read from the database is in UTC on PostgreSQL too, and a `postgres.Array` with a `NULL` element is an error.

### v0.3.1

No breaking changes. It cuts allocations and time on reads, tracking, saves and inserts, with the same API. The `dialect` and `qb` packages gain helpers for a dialect to write into ant's render buffer.

### v0.3.0

No exported name changed, but some behaviour did:

- `ant.Col(&f).Eq(nil)` and `.Ne(nil)` render `IS NULL` and `IS NOT NULL`, as `ant.Eq` and `ant.Ne` already did. They used to bind the nil and match no rows, so a query that relied on that can now return rows.
- A bulk `Update`, an upsert's `DoUpdate` or `Set`, a merge's `WhenMatched` and `UpdateMany` refuse an immutable, readonly or computed field with an error naming it, as `SaveChanges` always did.
- A migration that changes a column's type no longer casts with `USING` where PostgreSQL has a cast of its own, so a value too long for the new type fails the migration instead of being cut short.
- A `Tx` retry forgets what the failed run loaded or added, and a save after `MarkModified` stamps `UpdatedAt`.

The docs and examples now name a probe after its model in the plural, `Users = ant.Fields[User]()`, instead of `U`. That is a naming convention, not an API change: old code still compiles.

### v0.2.0

v0.2.0 made the first breaking change: the helpers that read or mark the change tracker now take a `context.Context`, and those that returned nothing now return an error.

| Before | v0.2.0 |
| --- | --- |
| `ant.Add(db, e)`, `Attach`, `Remove`, `MarkModified` | `ant.Add(ctx, db, e)`, and so on, returning `error` as before |
| `ant.Detach(db, e)` | `ant.Detach(ctx, db, e) error` |
| `ant.TrackGraph(db, root, decide)` | `ant.TrackGraph(ctx, db, root, decide)` |
| `ant.Tracked[T](db)` | `ant.Tracked[T](ctx, db) ([]*T, error)` |
| `ant.Entry(db, e)` | `ant.Entry(ctx, db, e) (*EntityEntry[T], error)` |
| `db.HasChanges()` | `db.HasChanges(ctx) (bool, error)` |
| `db.ClearTracked()` | `db.ClearTracked(ctx) error` |
| `db.DebugTracked()` | `db.DebugTracked(ctx) (string, error)` |

The context lets ant tell a hook that runs inside an operation from another goroutine using the same tracking context, which gets `ErrConcurrentUse`. Pass the context your hook or handler received. A call made with an unrelated context while another operation holds the tracker is refused.

`go build ./...` finds every call to change.

## From 1.0

ant will follow semantic versioning: patch releases fix bugs, minor releases add to the API and change nothing that exists, and major releases can break things, with notes on how to move.

The API is:

- Every exported name in the public packages, which a test keeps a record of in `docs/api.txt`.
- The behaviour the documentation and `tests/features` describe.
- The migration file format, and the history table.

The API isn't:

- Anything under `internal`.
- The exact SQL ant writes, which can change as long as it means the same.
- The text of error messages. Match errors with `errors.Is`.
- The `dialect` and `qb` packages, until a dialect outside this module exists to settle them.

## Files that outlive a release

Migrations and snapshots stay readable. A snapshot records its format, and a newer format is refused with a clear error, not misread. The history table only gains columns.

## Upgrade a project

1. Read the release notes for each version you cross.
2. Update the module: `go get github.com/skudra-go/ant@latest`.
3. Run `go build ./...`. A renamed or changed API fails here.
4. Run your tests against a real database.
5. Run `go run ./cmd/migrate check`. A release can change how a model maps to a schema; this shows it.
6. Run `go run ./cmd/migrate drift` against a staging database.

---
title: Hooks and observers
description: Run code around writes with model methods, and after the commit with observers.
---

A hook is a method on your model that runs inside the write. An observer runs after the commit and cannot change the write.

## Add a hook

Name the method for the hook and use a pointer receiver so changes to the entity are saved. This one lowercases emails on insert:

```go
type Member struct {
	ID    int64
	Name  string
	Email string
}

// spot-start
func (m *Member) BeforeInsert(ctx context.Context) error {
	m.Email = strings.ToLower(m.Email)

	return nil
}
// spot-end
```

| Hook | Runs |
| --- | --- |
| `Validate` | Before every insert and update |
| `BeforeInsert`, `AfterInsert` | Around an insert, and around an `Upsert` whichever way it goes |
| `BeforeUpdate`, `AfterUpdate` | Around a save that changed the entity |
| `BeforeDelete`, `AfterDelete` | Around a delete |
| `AfterLoad` | After a row is read |
| `AfterInclude` | After its relations are loaded |

An after hook runs once the row is written, so a change it makes to its entity, such as a slug built from the new key, is not in that write. On a session it is a change still to save, which the next `SaveChanges` writes.

```go
func (s *Story) AfterInsert(ctx context.Context) error {
	s.Slug = fmt.Sprintf("%s-%d", s.Name, s.ID)

	return nil
}
```

{/*
```go
type Story struct {
	ID   int64
	Name string
	Slug string
}
```
*/}

## Refuse a write

An error from a before hook stops the write. An error from an after hook undoes it, because hooks run inside the transaction.

```go
func (m *Member) BeforeDelete(ctx context.Context) error {
	// spot-start
	if m.Name == "protected" {
		return errors.New("cannot delete")
	}
	// spot-end

	return nil
}
```

For field rules, see [validation](/lifecycle/validation). To inspect or refuse a whole save, including a single `Insert`, before anything is written, use a [`SaveInterceptor`](/tooling/interceptors#watching-saves).

## Query from a hook

When the context has [change tracking](/tracking/sessions), a hook shares the operation's claim on the tracker through its `ctx`. Run hook queries with that context:

```go
func (m *Member) BeforeInsert(ctx context.Context) error {
	taken, err := db.Members.Where(ant.Eq(&Members.Email, m.Email)).Exists(ctx)
	if err != nil {
		return err
	}

	if taken {
		return errors.New("email is taken")
	}

	return nil
}
```

{/*
```go
type MembersDB struct {
	ant.Context
	Members ant.Table[Member]
	Notes   ant.Table[Note]
}

var Members = ant.Fields[Member]()
```
*/}

The hook's `ctx` is bound to the write's transaction, as by [`ant.InTx`](/transactions#code-that-holds-db). So the query runs in that transaction even through a global `db`, sees the rows the write has made so far, and waits on none of its locks.

A query with another context, such as `context.Background()`, runs outside the transaction. On a context with change tracking it also counts as a second operation on the tracker and returns `ant.ErrConcurrentUse`. Goroutines started with the hook's context share the claim and must not use the tracker concurrently.

## What runs no hooks

Bulk `Update` and `Delete`, `InsertMany`, `UpdateMany`, `Merge` and `Raw` run no hooks, since they load no entity. A save with nothing to save runs none either.

`ant.WithoutHooks` skips hooks for one call:

```go
// spot-next-line
err := db.Members.Insert(ant.WithoutHooks(ctx), member)
```

{/*
```go
var member *Member
```
*/}

## Write from a hook

A write a hook makes with its `ctx` is part of the write's transaction, so it commits or rolls back with it:

```go
func (m *Member) AfterInsert(ctx context.Context) error {
	// spot-next-line
	return db.Notes.Insert(ctx, &Note{MemberID: m.ID, Text: "joined"})
}

err := db.Members.Insert(ctx, &Member{Name: "Ann", Email: "ann@example.com"})
// BEGIN
// INSERT INTO "members" (...) VALUES (...) RETURNING "id"
// INSERT INTO "notes" (...) VALUES (...) RETURNING "id"   -- AfterInsert's
// COMMIT
```

{/*
```go
type Note struct {
	ID       int64
	MemberID int64
	Text     string
}
```
*/}

If a later part of the write fails, the note is rolled back too. For an audit log of every save, a [`SaveInterceptor`](/recipes/auditing) sees the whole save in one place.

Outside a transaction, a write of one row whose model has no After hook opens none, so what its Before hooks write commits on its own. Inside a `Tx` they run in that transaction.

For a write that must stay even when the outer write fails, such as a record of the attempt, give it `ant.InTx(ctx, db)` with `db` in no transaction, which unbinds the context:

```go
func (m *Member) BeforeDelete(ctx context.Context) error {
	// spot-next-line
	return db.Notes.Insert(ant.InTx(ctx, db), &Note{MemberID: m.ID, Text: "delete tried"})
}
```

A `Tx` inside a hook is a savepoint in the write's transaction. It takes no `Isolation`, which returns `ant.ErrNestedIsolation`, and `Attempts` does not retry it.

## Observe committed writes {#observers}

`ant.Observe` registers functions for one model. They run once the outermost transaction has committed, so an observer never sees a write that rolled back. Sessions made from the context share the observer.

```go
// spot-start
err := ant.Observe(db, ant.Observer[Member]{
	Inserted: func(ctx context.Context, m *Member) { welcome(m) },
	Updated:  func(ctx context.Context, m *Member) { refresh(m) },
	Deleted:  func(ctx context.Context, m *Member) { refresh(m) },
})
// spot-end
```

{/*
```go
func welcome(m *Member) {}

func refresh(m *Member) {}
```
*/}

Any of the three can be left nil.

### Write an audit log

An observer fires only for kept changes, so it suits a log line:

```go
err := ant.Observe(db, ant.Observer[Member]{
	Inserted: func(ctx context.Context, m *Member) {
		slog.InfoContext(ctx, "audit", "action", "insert", "model", "Member", "id", m.ID)
	},
	Deleted: func(ctx context.Context, m *Member) {
		slog.InfoContext(ctx, "audit", "action", "delete", "model", "Member", "id", m.ID)
	},
})
```

### Limits

- An observer runs in your process. If the process crashes between the commit and the call, it never runs. For anything that must not be lost, write an outbox row in the same transaction.
- A transaction from `UseTx` ends where ant cannot see it, so ant queues no observers for it and they never run. Writes in it are kept at once.

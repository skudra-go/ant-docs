---
title: Soft deletes
description: Mark rows as deleted instead of removing them, so a mistake can be undone.
---

A soft delete sets a timestamp on the row and hides it from queries. Add a field of type `ant.DeletedAt` to a model to turn it on.

## Turn it on

```go
type Note struct {
	ant.Base
	Text      string
	// spot-next-line
	DeletedAt ant.DeletedAt
}

var N = ant.Fields[Note]()
```

{/*
```go
type NotesDB struct {
	ant.Context
	Notes ant.Table[Note]
}
```
*/}

The column is a nullable timestamp. `NULL` means the row is live.

## Delete a row

`Delete`, `DeleteByID` and `ant.Remove` on a model with `DeletedAt` mark the row instead of removing it:

```go
n, err := db.Notes.Where(ant.Eq(&N.Text, "draft")).Delete(ctx)
// UPDATE "notes" SET "deleted_at" = $1
// WHERE "notes"."text" = $2 AND "notes"."deleted_at" IS NULL
```

```go
err := db.Notes.DeleteByID(ctx, id)
// UPDATE "notes" SET "deleted_at" = $1
// WHERE "notes"."id" = $2 AND "notes"."deleted_at" IS NULL
```

Deleting a row that is already marked changes nothing, and keeps the first timestamp. The delete does not touch `UpdatedAt`.

## Read live rows

Every query skips marked rows: `Find`, `Count`, `Include`, `Has`, joins and subqueries.

```go
all, err := db.Notes.All(ctx)
// SELECT ... FROM "notes" WHERE "notes"."deleted_at" IS NULL
```

## Read deleted rows

`WithDeleted` includes both, and `OnlyDeleted` returns the marked rows alone. A trash view is `OnlyDeleted`.

```go
every, err := db.Notes.WithDeleted().All(ctx)
// SELECT ... FROM "notes"

gone, err := db.Notes.OnlyDeleted().All(ctx)
// SELECT ... FROM "notes" WHERE "notes"."deleted_at" IS NOT NULL
```

## Restore a row

`Restore` clears the mark and returns how many rows it changed.

```go
n, err := db.Notes.Where(ant.Eq(&N.Text, "draft")).Restore(ctx)
// UPDATE "notes" SET "deleted_at" = $1
// WHERE "notes"."text" = $2 AND "notes"."deleted_at" IS NOT NULL
// -- $1 = NULL
```

On a model without a `DeletedAt` field, `Restore` returns `ant.ErrNotSoftDeleted`.

## Delete for good

`ForceDelete` removes rows for real. Add `WithDeleted` to reach rows that are already marked.

```go
n, err := db.Notes.WithDeleted().Where(ant.Eq(&N.Text, "draft")).ForceDelete(ctx)
// DELETE FROM "notes" WHERE "notes"."text" = $1
```

## Empty the trash

`Prune` removes matching rows for good, marked or not, in batches of 1,000, so it never holds one long transaction open. Run it from a scheduled job to purge rows deleted more than 30 days ago:

```go
cutoff := time.Now().AddDate(0, 0, -30)

removed, err := db.Notes.Prune(ctx, ant.Lt(&N.DeletedAt.V, cutoff))
// DELETE FROM "notes" WHERE "notes"."id" IN (
//   SELECT "notes"."id" FROM "notes" WHERE "notes"."deleted_at" < $1 LIMIT $2
// )
// -- $2 = 1000
```

A live row has a `NULL` timestamp, so `Lt` never matches it.

## Filter by when a row was deleted

`&N.DeletedAt.V` names the column as a time.

```go
stale, err := db.Notes.OnlyDeleted().Where(ant.Lt(&N.DeletedAt.V, cutoff)).Count(ctx)
// SELECT COUNT(*) FROM "notes"
// WHERE "notes"."deleted_at" IS NOT NULL AND "notes"."deleted_at" < $1
```

{/*
```go
var cutoff time.Time
```
*/}

ant binds `DeletedAt`, like every other time, in UTC on SQLite and SQL Server, whose columns keep no time zone. A `DeletedAt` stored from a server in another zone compares correctly. See [databases](/reference/databases).

## Reuse a unique value

A marked row still holds its values, so a plain unique constraint stops anyone from reusing its email. Index only the live rows:

```go
func (User) Configure(b *ant.ModelBuilder[User]) {
	// spot-next-line
	b.Index(&U.Email).Unique().Where("deleted_at IS NULL")
}
```
